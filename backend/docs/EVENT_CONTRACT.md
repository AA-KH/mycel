# Event Contract

In Mycel, the backend must decouple execution state from visualization state. 

Currently, agents update MongoDB and push directly to a WebSocket manager. In the future architecture, all state changes will be published as normalized events to an internal Event Bus (or RabbitMQ), which will then be consumed by the realtime WebSocket gateways.

## Normalized Event Schemas

All events should follow a standard schema structure, allowing any consumer (logger, evaluator, or UI visualizer) to parse them consistently.

```json
{
  "event_id": "evt_abc123",
  "timestamp": "2026-08-23T02:00:00Z",
  "type": "agent.working",
  "source": "execution_engine",
  "payload": {
    "task_id": "task_456",
    "employee_id": "emp_01hqxyz9",
    "message": "Generating final response..."
  }
}
```

## Task Events

Task events represent the overarching workflow lifecycle managed by the Orchestrator.

- **`task.created`**: The user has submitted a new task.
- **`task.started`**: The Orchestrator has begun analyzing and planning the task.
- **`task.completed`**: All subtasks are finished, artifacts are verified, and the project is done.
- **`task.failed`**: The task could not be completed (e.g., all retries exhausted, or catastrophic error).

## Agent (Employee) Events

Agent events represent the microscopic lifecycle of a single Employee executing a subtask. These events directly drive the pixel-art office UI (e.g., making a sprite type at a computer, pace, or read a book).

- **`agent.assigned`**: An employee has been hired for a task but hasn't started yet.
- **`agent.started`**: The employee has received the context.
- **`agent.thinking`**: The employee's reasoning profile is active (planning/decomposing).
- **`agent.working`**: The employee is actively generating output or interacting with the system.
- **`agent.waiting`**: The employee is blocked (e.g., waiting for a long tool execution or human input).
- **`agent.reviewing`**: The employee is critiquing their own output or another employee's output.
- **`agent.completed`**: The employee successfully fulfilled their assigned node.
- **`agent.failed`**: The employee failed to complete their assigned node.

## Tool Events

Tool events provide visibility into the sandboxed Execution Gateway.

- **`tool.started`**: A tool execution has commenced.
- **`tool.completed`**: A tool execution succeeded and returned data.
- **`tool.failed`**: A tool execution failed (e.g., rate limit, timeout, or access denied).

## Artifact Events

Artifact events provide visibility into the physical delivery pipeline.

- **`artifact.created`**: The raw data was generated by the LLM/Tool.
- **`artifact.validated`**: The `ArtifactValidator` confirmed the structural integrity.
- **`artifact.uploaded`**: The physical file was safely stored (e.g., Cloudinary).
- **`artifact.delivered`**: The user received the final artifact payload.
